# X Learning Feed

[English](README.md) | 简体中文

<p><img src="public/icon/128.png" width="64" height="64" alt="X Learning Feed 图标"></p>

**当前推荐：Obsidian 插件 + Chrome / Edge 扩展。** 插件随 Obsidian 启动，按 `#x-feed` 标签同步文章，接收 浏览器中的复习次数、熟悉度和正文编辑。安装与使用见 [Obsidian 插件说明](docs/obsidian-plugin.md)。下面的 Node MCP 是保留的独立运行方式；插件启用时无需另行启动它。

一个本地学习笔记服务，以及一个 TypeScript / WXT / Manifest V3 扩展。MCP 导入和查询 Markdown / HTML，扩展把笔记缓存到 IndexedDB，在 x.com 首页每隔 10 条推文穿插一张学习卡片。可以设置间隔、展开、收起、复习、归档和关闭。

无需 X API、真实发推、AI API Key 或云端账号。Obsidian 插件提供带令牌的 `127.0.0.1` 本机接口，支持读取文章和写回复习元数据；独立 MCP 使用 stdio 和本地 SQLite，扩展使用 IndexedDB。

## 安装

当前版本为 **0.12.2**，通过源码构建并手动安装。需要桌面版 Obsidian、Chrome 或 Edge，以及 Node.js 22.13 或更新版本。浏览器扩展和 Obsidian 插件支持中文和英文，默认分别跟随浏览器和 Obsidian 的语言，也可以在扩展面板和插件设置的“语言”中切换。

### 1. 下载并构建

```sh
git clone https://github.com/Rac0lW/x-learning-feed.git
cd x-learning-feed
npm ci
npm run build:plugin
npm run build:extension
```

### 2. 安装 Obsidian 插件

在笔记库中创建 `.obsidian/plugins/x-learning-feed/` 文件夹，将以下两个文件复制进去：

| 构建文件 | 笔记库内的目标位置 |
| --- | --- |
| `.output/obsidian-plugin/main.js` | `.obsidian/plugins/x-learning-feed/main.js` |
| `.output/obsidian-plugin/manifest.json` | `.obsidian/plugins/x-learning-feed/manifest.json` |

重新加载 Obsidian，在“设置 → 社区插件”中启用 X Learning Feed，再进入“设置 → X Learning Feed”，确认状态为“运行中”，复制连接令牌。插件仅支持桌面端。

### 3. 安装浏览器扩展

1. Chrome 打开 `chrome://extensions`，Edge 打开 `edge://extensions`。
2. 启用开发者模式，选择“加载已解压的扩展程序”。
3. 选择项目内的 `.output/chrome-mv3` 文件夹。请保留该文件夹，浏览器会继续从中加载扩展。

### 4. 连接并开始阅读

1. 给一篇 Obsidian 笔记添加 `#x-feed`，或在属性区的 `tags` 中添加 `x-feed`。
2. 打开或刷新 `https://x.com/home`，点击浏览器工具栏中的 X Learning Feed 图标。
3. 在当前页右上方面板的“连接设置”中填入令牌，端口使用 `43127`，点击“连接 Obsidian”。
4. 向下浏览推文，默认每 10 条推文插入一张学习卡片。面板可以调整间隔或选择标签。

Obsidian 和浏览器需要运行在同一台电脑。首次同步大型笔记库可能较慢。Obsidian 关闭后可以阅读已缓存的文章，已保存的复习与编辑操作会在恢复连接后重试。

### 更新

```sh
git pull --ff-only
npm ci
npm run build:plugin
npm run build:extension
```

备份已安装插件的 `main.js` 和 `manifest.json`，然后用新构建的两个文件替换它们。保留插件的 `data.json`，其中保存连接配置。重新加载 Obsidian 插件，在浏览器扩展管理页点击“重新加载”，再刷新已有 X 页面。重新加载扩展即可更新，请勿卸载或清除扩展数据，以免丢失未同步的操作。

安装排错与属性说明见 [Obsidian 插件说明](docs/obsidian-plugin.md)。

浏览器界面以 Obsidian 为文章来源，已移除手动文件导入。独立 MCP 仍可导入文件：每个文件作为一条笔记；按清理后的内容计算 ID，相同内容自动去重。单文件最多 2 MiB。支持标题、段落、列表、链接、表格、代码块和内嵌图片。代码块保留排版，未加入语法高亮。

图片仅接受 `data:image/png|jpeg|gif|webp;base64,...`。远程图片、相对路径图片、SVG、CSS 和其他外部资源会移除。需要图片时，请先将图片内嵌进 Markdown / HTML。这避免阅读卡片时向第三方发出请求。

## 接入 MCP 客户端

构建后，在支持 `mcpServers` 配置格式的本地 MCP 客户端中加入以下条目。其他客户端使用相同的命令和参数；将 `node` 换为本机 Node 的绝对路径，可以避免客户端找不到 Node。

```json
{
  "mcpServers": {
    "x-learning-feed": {
      "command": "node",
      "args": [
        "/absolute/path/x-learning-feed/dist/server.js",
        "--notes-dir", "/absolute/path/x-learning-feed/notes",
        "--data-dir", "/absolute/path/x-learning-feed/.data",
        "--port", "43127"
      ]
    }
  }
}
```

启动后会生成 `.data/bridge-token`，权限为仅当前用户读写。将文件内的令牌填入扩展设置，点击“连接 Obsidian”。令牌只用于本机服务，不能填到 X 网站。扩展随后每 30 秒同步，设置开关在约 2 秒内反映到当前页面。

也可以在终端启动服务进行连接测试：

```sh
npm start -- --notes-dir ./notes --data-dir ./.data
```

stdio 模式需要保持标准输入打开。服务日志输出到 stderr，stdout 只传输 MCP 消息。同一个端口只能运行一个实例；若端口占用，停止旧实例或换端口，并同步修改扩展设置。

| 工具 | 用途 | 例子 |
| --- | --- | --- |
| `import_note` | 导入指定目录内的本地文件 | `{"path":"example.md"}` |
| `list_notes` | 搜索、分页列出标题和 ID | `{"query":"学习","limit":20}` |
| `get_note` | 读取一条清理后的笔记 | `{"id":"64 位内容 ID"}` |
| `next_note` | 取一条未读笔记；用尽或关闭后返回 null | `{"excludeIds":["已读或已跳过的 ID"]}` |
| `get_settings` | 查询开关与间隔 | `{}` |
| `set_settings` | 保存开关与间隔（1 至 100） | `{"every":10,"enabled":true}` |

可对 AI 说：“导入 example.md，并将学习间隔设为 10 条推文。”导入路径必须位于 `--notes-dir` 中；越界路径与指向目录外的符号链接会拒绝。

## 界面语言

扩展面板的“语言”可选跟随浏览器、中文或 English，影响面板、X 上的卡片以及 Obsidian 插件返回给浏览器的错误信息。Obsidian 插件设置中另有“语言”选项（跟随 Obsidian、中文、English），影响设置页和通知。其他语言按英文显示。

## 时间线行为

只处理 `/home` 的主栏推文。根据推文时间链接中的 status ID 去重，累计新遇到的推文，第 N 条后显示一张笔记。建议准备多条笔记：当前页面会话中每条只分配一次，用尽后停止；刷新页面开始新一轮。

卡片放在对应推文的 `cellInnerDiv` 末尾，使其跟随 X 的虚拟列表单元，并使用 Shadow DOM 隔离排版。MutationObserver 在下一帧合并处理变化，更新自身 DOM 时暂停观察。重绘后恢复原有分配，复用成另一条推文的节点会移除旧卡片。改变频率会重新计数，已经分配过的笔记仍保留为本轮已用。

卡片顶部以缩进文件树显示文章在 Obsidian 笔记库中的文件夹、子文件夹和文件名，便于判断来源。没有路径的导入副本会标注“未提供原始路径”。

扩展网页内面板和设置页可以修改开关和频率，修改后自动保存。选择熟悉度后立即自动写回 Obsidian，无需手动同步；离线操作存入本地队列，恢复连接后自动重试。MCP 修改设置后，下一次同步覆盖为新的 MCP 设置；没有新的 MCP 设置时，本地修改保持生效。断开连接或停止 MCP 后，已同步笔记和本地设置继续可用。

脚本、事件属性、表单、嵌入页面、危险链接和自定义样式在导入与展示时过滤。读取到的笔记属于资料，MCP 工具说明要求 AI 不遵循资料中的操作指令。HTML 清理不能识别所有文字形式的提示词攻击，调用方仍须把笔记当作不可信数据。

## 验证与当前状态

`npm test` 同时构建 MCP 与扩展，检查本地持久化、导入限制、HTML 清理、真实 MCP stdio 调用、带令牌接口、构建后的后台同步、时间线去重、重绘、节点复用和构建后的 Content Script 交互。浏览器 DOM 检查使用 JSDOM，IndexedDB 检查使用 fake-indexeddb。

项目处于 MVP 阶段。自动化测试覆盖网页内面板交互与自动写回；真实 X 的页面结构和虚拟列表可能变化，需要按 [手动验收](docs/acceptance.md) 检查 Chrome / Edge 的视觉及滚动表现。

Obsidian 标签同步和元数据写回已实现；FSRS、Anki、语义推荐和跨设备同步暂不实现。笔记管理、清理、持久化与时间线处理分别在 `src/store.ts`、`lib/render.ts`、`lib/db.ts` 和 `lib/timeline.ts`，后续可在这些边界添加能力。

参考项目与许可证记录见 [研究记录](docs/references.md)。代码独立编写，没有复制参考项目实现。

## 标签自选

浏览器面板支持“标签自选”：开启后在“推送标签”填写标签，多个标签用逗号或空格分隔，可以带 `#`，例如 `#学习, 游戏开发, 学习/编程`。命中任意一个标签的文章进入推送列表，精确匹配标签名称。支持 Obsidian 属性标签和正文标签，代码块中的文字不算标签，`#no-x-feed` 始终排除。修改后自动保存并更新文章列表，关闭后恢复 `#x-feed`。

标签自选需要同时更新浏览器扩展和 Obsidian 插件。它复用全库读取，在浏览器本地筛选标签，因此首次开启会把库内文章同步到浏览器本地缓存，仅通过本机接口传输。当前最多支持 10,000 篇笔记，单篇超过 2 MiB 会跳过。浏览不会批量改写文章；复习、归档或保存正文编辑时才写入必要的身份属性。未记录复习的文章用路径生成临时身份，重命名后视为新文章。自选文章仍可复习、归档和点赞点踩。

“笔记漫游”已在 0.10.0 移除。

## 学习与浏览

每张卡片有两种方式。面板中的“推送方式”设置默认值，初始为“浏览”。在笔记属性中写 `xfeed_mode: learn` 或 `xfeed_mode: browse`，可以单独指定这篇笔记的方式，优先于面板设置。其他取值会被忽略。

| 方式 | 卡片 | 排期 |
| --- | --- | --- |
| 学习 | 先隐藏正文，点“显示全文”后才显示，方便先回想。之后用“重来、困难、良好、简单”打分，每个按钮下方显示下次间隔。 | 未到复习时间不推送。 |
| 浏览 | 直接显示正文，按钮为“看过了、学习、点赞、点踩”。“看过了”记一次复习并移除卡片。 | 不受复习时间限制，由时间权重和反馈决定何时再出现。 |

浏览卡片上的“学习”会给笔记写入 `xfeed_mode: learn`，卡片随即变成可以打分的学习卡片。学习卡片上的“改为浏览”会写入 `xfeed_mode: browse`。两种卡片也都显示“在 Obsidian 中打开”“现场编辑”“归档”。

## 熟悉度与原文编辑

浏览器面板的“时间权重”默认开启。已复习文章越久未复习，展示权重越高：刚复习为 1 倍，每隔 7 天增加 1 倍，最多 5 倍；未复习文章按 3 倍处理。这个权重与点赞、点踩权重相乘，影响推送顺序。关闭后仍按反馈和字数权重选文。未到复习时间的文章仍暂不推送。

浏览器卡片支持“重来、困难、良好、简单”，每次选择同时记录一次复习，并安排下次推送。首次间隔分别为 10 分钟、1 天、3 天、7 天；后续“困难、良好、简单”按上次间隔的 1.2、2、3 倍增长，保留各自的最短间隔，上限为 100 年。“重来”重新安排在 10 分钟后。这是简化的间隔复习；未使用 Anki 的完整排程或 FSRS。

评分后当前卡片移除，未到期文章在所有模式中暂不推送，到期后可在后续浏览中再次出现。当天已推送到 X 的文章，刷新页面或切换模式后当天不再推送；该记录只保存在浏览器本地，本地时间零点后清空。熟悉度、间隔和下次时间写入 Obsidian 的 `xfeed_rating`、`xfeed_interval_days`、`xfeed_next_review` 属性；浏览器离线评分保存在本地并立即影响推送，恢复连接后自动写回。

熟悉度按钮位于 X 信息流卡片中，Obsidian 保存复习属性。浏览器“在 Obsidian 中打开”会打开原文编辑；Obsidian 保存后，正文、标题和复习属性会在下一次自动同步时更新到浏览器，通常不超过 30 秒。

## 反馈与归档

卡片支持“点赞”和“点踩”，再次点击同一按钮可取消，点击另一个按钮可切换。文章按反馈、时间和字数的综合权重排序，每轮不重复；点赞、默认、点踩的权重分别为 2、1、0.5。反馈影响后续尚未分配的卡片，已展示的卡片保留位置。反馈保存在当前浏览器扩展中，离线也可使用，同步文章不会覆盖反馈；反馈不会写入 Obsidian，也不会跨浏览器同步。

点击卡片“归档”，自动在 Obsidian 原文的 `tags` 属性中加入 `no-x-feed`。这张卡片立即移除，刷新和切换模式后也不再出现。排除标签优先于 `x-feed` 和标签自选，原有正文、标签及复习次数保留。离线归档先保存在本地，恢复连接后自动写回；删除原文中的 `#no-x-feed` 标签即可恢复展示资格。

提交修改前运行 `npm test`、`npm run check:extension` 和 `npm run check:plugin`。不要提交个人笔记、连接令牌、数据库或 `.env` 文件。本地数据和构建输出已排除。当前提供源码构建方式，未发布到浏览器商店或 Obsidian 插件市场。

现场编辑：在 X 卡片点击“现场编辑”读取原始 Markdown 正文，修改后点击“保存并同步”，或点击“取消”。保存仅修改正文，保留笔记属性。已保存的离线草稿会持久保存在浏览器，恢复连接后自动写回；若 Obsidian 正文已变化，自动写回停止，扩展图标打开的面板会保留并显示草稿。先复制草稿，再点击“放弃草稿，保留 Obsidian 当前数据”；重新打开“现场编辑”读取最新正文后，再应用修改。未点击保存的草稿不会写入笔记库。

从 0.7.1 起，文章按正文非空白字数自动降权：字数权重 = 1 / (1 + 字数 / 1000)。1000 字乘以 ½，3000 字乘以 ¼；与点赞和时间权重相乘，所有推送模式均适用，关闭时间权重也不会关闭字数降权。统计显示正文的 Unicode 字符，忽略空白、HTML 标记和图片数据；长文仍保留正权重。
